# Agent Garden experimental labs

These standalone Godot prototypes explore image-driven property viewing, car inspection/driving, and a small locally trained navigation network. They are separate from the core Garden MCP server and its authoritative verifier. Start with each lab's README for scope and historical results.

| Lab | Entry points | Requirements |
|---|---|---|
| [Home](home/) | `home-worker.gd` + `record-home.mjs`; `walk-worker.gd` + `record-walk.mjs` | Godot 4.7.2, Node with `npm ci`, Codex CLI with an existing login, credited apartment GLB |
| [Showroom](showroom/) | `drive-worker.gd` + `record-drive.mjs`; `dramatic-worker.gd` + `record-dramatic.mjs`; `showroom-worker.gd` + `record-showroom.mjs` | Same tools, credited car GLB and panorama GLB |
| [Navigation](navigation/) | `play.cmd`, `watch-navigation.cmd`, `run-navigation.cmd` | Godot 4.7.2, credited lobby/character GLBs; Python with NumPy/PyTorch for training |

The home and showroom recorders launch Codex CLI using the user's own login. They are fresh agent runs and can consume that account's usage. The navigation collector, trainer and FFN controller do not call an LLM or API. Other agents can implement the exposed MCP tools, but these example recording launchers specifically invoke Codex; universal CLI compatibility has not been tested.

## Download assets separately

See [THIRD_PARTY_ASSETS.md](THIRD_PARTY_ASSETS.md) for **creator attribution, source links, exact filenames, licenses and modifications**. GLBs, extracted textures and geometry caches are not redistributed in this repository. Downloads may require an account on the source site. Retain their license and attribution notices when making your own demo.

Place the models at the documented paths manually, or use this standard-library-only helper from the repo root:

```powershell
python labs/prepare_assets.py --apartment "path/to/modern_apartment.glb"
python labs/prepare_assets.py --car "path/to/ferrari.glb" --environment "path/to/gotthard.glb"
python labs/prepare_assets.py --lobby "path/to/lobby.glb" --character "path/to/kana.glb"
```

The helper copies local files without overwriting existing assets and extracts the Gotthard model's embedded PNG panorama for the showroom sky. It does not download anything.

## Run home or showroom

Run `npm ci` in the chosen lab. Open two terminals in that lab's directory. Set `GODOT_BIN` to the executable, or put `godot` on PATH. For example:

```powershell
# Terminal 1, inside labs/home
& $env:GODOT_BIN --path . --script walk-worker.gd --rendering-method forward_plus --resolution 1280x720
# Terminal 2, inside labs/home, after HOME_READY
node record-walk.mjs
```

For showroom use `showroom-worker.gd` and `record-showroom.mjs`, waiting for the worker's ready message. Use matching worker/recorder pairs from the table. Only one worker may write to a session directory at a time. Workers create their session directories; preserve existing outputs before repeating a recording. Stop the worker when finished. The initial home viewing variant uses `home-worker.gd` with `record-home.mjs`.

The `make-*.py` programs are historical video-edit recipes for the original sessions, not general render pipelines. They require Pillow, ffmpeg, Windows Segoe UI fonts, matching session captures and, for car social edits, the soundtrack generated by the home social-edit recipe. Exact original raw image sessions are not included. Finished videos remain in [docs/media](../docs/media/).

## Run navigation

After preparing the lobby and character assets, start `navigation/play.cmd` once with graphics enabled. This bakes collision geometry from the visible skinned pose into an ignored local cache. Close it before automated runs. `watch-navigation.cmd` then runs the included learned policy on the documented illustrative test task; it is not a replay of preset actions. `run-navigation.cmd` regenerates tasks, demonstrations, correction data, training and held-out evaluation into a fresh timestamped directory.

Set `GODOT_BIN` and optionally `PYTHON_BIN`, or put `godot` and `python` on PATH. Install the Python requirements from `navigation/training/requirements.txt`; choose a PyTorch build suitable for your hardware. CUDA is optional. The published experiment includes selected weights, all 50 test outcomes/trajectories, task definitions and summary reports. Large raw training records, historical per-seed checkpoints and generated caches remain local; rerunning the pipeline recreates them. Original results were measured on the original machine before the public-path cleanup. This is a one-lobby start-goal holdout, not unseen-building generalization.
